Four rules that hold everywhere
2
1. The system draws playbackEncore feeds the Now Playing data. It never draws a second player on the lock screen.
2. A Live Activity is for a timed taskThe sleep timer, a download or the first sync, and only when the person started it.
3. A widget shows what the app savedA small snapshot per profile, on the device. No database, no network.
4. Nothing needs a push serviceNo push token leaves the device. The running app updates everything.

1
What each platform gets. Every platform gets the surfaces it really has and nothing is faked where the system has none. Mac has no lock screen widgets and Linux has no widgets in version 1. Windows has no lock screen widgets for any app. Where a platform has a timed-task surface, the sleep timer, a download the person started and the first sync use it; everything else is a normal notification at most, and often not even that.
2
The four rules. Playback is drawn by the system from the Now Playing data, so there is never a second player. A Live Activity or Live Update starts only from something the person did. A widget reads only the small snapshot the app saved for that profile on the device. Nothing uses a push service, because a self-hosted server has no push key and listening state would otherwise pass through a third party.
3
Settings page. Settings › Lock screen and widgets has four rows: Sleep timer on the Lock Screen (a Live Update on Android), Download progress on the Lock Screen, Hide listening history while locked (on) and Widget profile (Active profile). Turning a card off never stops the timer or the download, it only removes the card. If the system has Live Activities or Live updates off for Encore, a note says so and, on Android, a button opens the system page. The page plays no custom haptics.
4
Sleep timer sheet. Opened from More on Now Playing, from Settings › Playback and quality, from the Sleep timer Control and from a tap on the Live Activity. Presets are 5, 10, 15, 30, 45 and 60 minutes, End of this song and End of this album; the end time is shown under the Start button before anything starts. While it runs the sheet shows the time left, Add 15 min, Cancel timer and Change time. An accidental tap on the scrim or a swipe down closes the sheet and leaves the timer running. Cancel timer shows Timer cancelled with Undo for five seconds. End of song and End of album let the song play to its end and then pause, with no fade.
5
States and the clock. The end time is stored with the profile's player state, so the timer survives the app being restarted. At the end the music pauses, the Live Activity ends at once (the Dynamic Island removes it immediately; the Lock Screen may keep it up to four hours, so Encore ends it itself) and a finished download stays 15 minutes. Without push, the Live Activity gets a stale date equal to the end time. If the app was killed, the system greys the card and the next launch removes it; on Android the notification has a timeout at the end time.
6
Privacy. A passer-by sees only what the system player already shows on a locked phone, plus that a timer or download is running. Personal text in widgets is marked privacy sensitive on Apple devices, and widgets that show history are kept off the Android lock screen. Hide listening history while locked is on by default. A profile with a PIN, and the guest profile, show the neutral Open Encore card. No Live Activity shows an advertisement or a promotion.
7
Profiles. Each widget has a Profile setting, Active profile by default. A widget set to one profile keeps showing that profile after the switcher changes; a deleted profile's widgets say Profile removed. The sleep timer card names no profile and shows no history, so switching profile needs no change to it.
8
When posting is off. If Live Activities are off in iOS Settings, Encore shows the timer only in the app and in the system player; it never asks twice in a session. On Android, when the system Live updates setting is off or the phone is older than Android 16 QPR1, the same words appear in a normal ongoing notification in a low-importance channel, and the banner on this page links to the system setting. Unwanted Live Updates make people revoke the permission, so none starts without something the person did.
9
Haptics, motion and accessibility. Widgets and Live Activities run outside the app, so the system's feedback applies, and the app plays its usual haptic only when it handles the action in the foreground: a selection tick on a preset, a light impact on Start, nothing on Cancel. VoiceOver, TalkBack and Narrator read Sleep timer, 24 minutes left, and the button Add 15 minutes. Text follows Dynamic Type and font scale until the layout would clip, then drops a line. Animations last at most two seconds and stop under Reduce Motion and on Always-On.
10
To test on real hardware. The simulator and emulator do not show Always-On, Low Power Mode, Focus filtering, StandBy at night or CarPlay. Check: the activity ends on time, a +15 min tap adds time at once, a long download that the system pauses, an Android 15 phone, an Android 16 phone with Live Updates off, a tablet, Windows packaged and unpackaged builds, light and dark everywhere, and GNOME and Plasma on Wayland. Not checked in this pass: whether Google Play treats a download-progress Live Update as eligible.
How to read the boards. The next three boards draw each surface: Lock screen and Live Activities, Widgets and controls on Apple devices, and Widgets and media surfaces on Android, Windows and Linux. Dashed outlines mark what the system draws. Version 1 has no Apple Watch app, no Wear OS app and no Android Auto layout; the Watch and CarPlay views come from the iPhone Live Activity.
