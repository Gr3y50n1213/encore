# ADR core-0023: Plex Media Server

Date: 26 November 2026
Status: proposed (Phase 12 stage 2; the sign-in screen waits for the owner's mock-up)

## Context
Phase 12 adds media servers behind `MediaSource` with no UI change except signing in. Plex differs from Jellyfin and Subsonic in three ways that shape everything below. A person signs in to Plex once, at plex.tv, not to a server; a server is reached with a token plex.tv issues for it. A server can have several addresses (on the home network, from outside, through Plex's relay), and plex.tv is where they are listed. And the server has no call that says who a token belongs to. The owner has no Plex server or account, so everything that touches plex.tv is tested on hand-made fixtures, and the server side against a real, unclaimed Plex Media Server in CI.

## Decision
1. **One adapter, `encore-sources/src/plex/`**: `PlexClient` (the server's API), `PlexTv` (plex.tv), `PlexSource` implementing `MediaSource`, and `SourceKind::Plex` ("plex" in the database). Every request asks for JSON (`Accept: application/json`) and sends the token as the `X-Plex-Token` header, never in a URL, except `StreamInfo::url_with_api_key` for players that can't send headers (the same rule as Jellyfin). `Request`, `StreamInfo`, `PlexCredentials`, `PlexPin`, `AccountToken` and `PlexServerResource` hide tokens and codes from Debug output.
2. **Signing in is the plex.tv PIN link.** `POST https://plex.tv/api/v2/pins?strong=false` makes a four-character code. The user enters it at plex.tv/link, or opens Plex's sign-in page with the code filled in (`https://app.plex.tv/auth#?clientID=...&code=...&context[device][product]=Encore`). The core polls `GET /api/v2/pins/{id}` until it carries the account token; a 404 means the code expired. Then `GET /api/v2/user` gives the account's number and user name (nothing else is read: not the e-mail, not the picture), and `GET /api/v2/resources?includeHttps=1&includeRelay=1&includeIPv6=1` lists the account's servers (`provides` contains "server") with each server's own `accessToken` and its connections. Whether Plex's sign-in page takes a short (non-"strong") code as well as plex.tv/link does is not verified; if it doesn't, the UI shows only the code.
3. **What plex.tv sees, and when.** The app contacts plex.tv only to sign in (the calls in point 2) and to look up a server's addresses when none of the known ones answers (point 5). Every request names the product "Encore", its version, the platform name and a client identifier made for Plex: SHA-256 of a fixed label and the install's random device ID (`client_identifier`), so it is stable per install, is not the device ID, and links nothing to the companion or another server. The device's name is never sent (`X-Plex-Device-Name` is the product name). The account's picture lives on plex.tv, so a Plex profile shows initials.
4. **Only the server's token is kept.** The account token lives in memory while the link screen is open, and is dropped once a server is chosen, the link is cancelled or the code expires. The keychain gets `plex1:t=<server token>&m=<machine ID>&c=<address>...` (form-encoded): the chosen server's `accessToken`, its `machineIdentifier`, and its addresses in the order to try them.
5. **Choosing and keeping an address.** A server's connections are tried local before remote, https before http, relay last; plain http away from the local network is dropped (board 21). The first address whose `/identity` names this server and that takes the token (`/library/sections`) is used. When it stops answering, the client tries the other saved addresses (each must name the same `machineIdentifier`), and then, at most every ten minutes, asks plex.tv's `/api/v2/resources` with the server token for the addresses it lists now. Whether plex.tv takes a server token there (it is the account's own token for some servers, a per-share token for others) is not verified; when it doesn't, the source fails as unreachable and the user signs in again. The new address is used in memory only; the saved list is the sign-in's.
6. **Finding a Plex server from a typed address.** `check_address` asks Jellyfin first, then Subsonic, exactly as before; only when neither answers does it ask `GET /identity` (no sign-in needed on any Plex server, claimed or not) on the same addresses and then on Plex's own port 32400. It returns `ServerKind::Plex` with the `machineIdentifier` as `server_id`, so the UI can send the user to the link and pick that server from the list. An untrusted certificate on a Plex address is reported so it can be trusted. If none answers, the Jellyfin error comes back as before.
7. **Library mapping.** Music libraries are the sections of `type=artist`. Artists, albums and tracks are types 8, 9 and 10 of `/library/sections/{id}/all`, paged with `X-Plex-Container-Start` and `-Size` (`totalSize` says when to stop). A track's album is its parent, the album's artist its grandparent, `originalTitle` its own artist when different; durations are milliseconds, `addedAt` seconds; MusicBrainz IDs come from the `Guid` list. A track's ID is `<ratingKey>:<part ID>`: playlists, ratings and metadata take the rating key, while streaming, downloads and sound analysis need the file (`/library/parts/<part>/file`), and `stream_info` can't make a request to look it up. A track whose file changes gets a new ID (its history follows by song key).
8. **"Nothing changed" syncs.** Every section has a `contentChangedAt` counter that moves when its content changes and not on ratings, plays or playlist edits (checked in CI). The cursor keeps each section's counter and when the last full sync ran: `plex1:s=<key>.<counter>,...;full=<ms>`. When no counter moved, no section came or went, and the last full sync is under a day old, the sync is light: the playlists (whole, so one deleted elsewhere goes) and the favourites (`userRating>>=8`, one listing per section). Play counts from other apps come with the daily full sync.
9. **Favourites, playlists, lyrics, covers, streams.**
   - *Liked* is a rating of 4.5 stars or more (`userRating` 9 or 10): what Plexamp's "love" and a five-star rating give, and not an ordinary four-star rating. A like writes five stars (`PUT /:/rate?key=&identifier=com.plexapp.plugins.library&rating=10`); an unlike clears the rating (`rating=-1`), so unliking a 4.5-star song removes its stars.
   - *Playlists* (`/playlists?playlistType=audio`; Plex lists only the user's own; smart ones are read-only): create `POST /playlists?type=audio&smart=0&title=&uri=server://<machine>/com.plexapp.plugins.library/library/metadata/<keys>`, add `PUT /playlists/{id}/items?uri=`, remove `DELETE /playlists/{id}/items/{playlistItemID}`, move `PUT .../items/{entry}/move?after={entry}` (none: to the top), rename `PUT /playlists/{id}?title=`, delete `DELETE /playlists/{id}`. Adding at a position adds at the end and moves the new entries into place. Plex keeps a song once per playlist: adding one already there is ignored by the server (seen in CI), and the next sync shows the list as it is.
   - *Lyrics* are a track's lyric streams (`streamType` 4, from a sidecar `.lrc` or `.txt`, or the server's lyrics agent), read from `/library/metadata/{key}` and fetched by their key (`/library/streams/{id}`); a stream with codec "lrc" is LRC, others plain. The listing doesn't say which tracks have lyrics, so each is asked once (cached as for every source).
   - *Covers* come from the photo transcoder (`/photo/:/transcode?width=&height=&url=<thumb>`); colour sampling asks it for PNG (`format=png`). An album's `thumb` (`/library/metadata/<id>/thumb/<time>`) is its artwork tag.
   - *Streams*: the original is the part's file; a bitrate cap uses the universal music transcoder (`/music/:/transcode/universal/start.mp3`, progressive MP3 over HTTP with `musicBitrate`), which needs the profile addition `add-transcode-target(type=musicProfile&context=streaming&protocol=http&container=mp3&audioCodec=mp3)`: without it the server says "No conversion profile found for protocol http" (seen in CI). Downloads take the part with `download=1`; sound analysis reads it in ranges.
   - *Plays*: `viewCount` and `lastViewedAt` are read into the server play counts. Encore doesn't report plays to any media server (the companion keeps the history), so `playback_reporting` stays false; `PlexClient::scrobble` exists for the CI test that stands in for another Plex app.
   - *Capabilities*: lyrics, transcoding and writable playlists are true; Quick Connect is false (the plex.tv link is told apart by `ServerKind::Plex`, not by a capability).
10. **The companion.** A device sends `plex1:t=<server token>&m=<machine ID>` (no addresses) as `media_token`. The companion tries its trusted media URLs: the one whose `/identity` names that machine, and the server ID the device sent, is used. It first sends a made-up token; if the server takes it (an unclaimed server, or one whose "allowed without auth" networks include the companion), it can't vouch for any token and the sign-in is refused with a message saying why. Then the device's token must be taken (`/library/sections`). Plex Media Server has no call that names a token's account, and the companion never calls plex.tv, so the companion names the account `plex:<hash of machine ID>:<hash of token>`: a token reaches only its own profile, and nothing the device claims can change that. Two devices share a companion profile only if the server gave them the same token: true for a server shared with the account (one token per share), most likely not for the owner's own server, whose token is per sign-in. Joining the owner's devices would need plex.tv's `/api/v2/user` from the companion; that is the owner's call (see Open).
11. **Testing.** Fixture tests for the adapter, plex.tv included (`tools/fixtures/plex/`, invented data, a fake plex.tv served by the fixture transport) and for the core's link flow; nothing contacts the real plex.tv. In CI (`core.yml`, job `plex`) a real Plex Media Server 1.43.5, pinned by digest, runs unclaimed on a Docker network with no route out (`--internal`, and plex.tv names pointed at nowhere), so neither it nor the test can reach plex.tv. `ALLOWED_NETWORKS` lets the runner in without a sign-in, the only way into an unclaimed server. The library uses the "Plex Personal Media" agent with the "Plex Music" scanner, which reads tags, `cover.jpg` and the `.lrc` sidecar offline (the "Plex Music" agent needs Plex's online metadata service). The ignored test `plex_flow_over_http` signs in from the server's address with the token the server takes (a test-only call; the app's only way in stays the link) and then runs the app's own path.

## What CI can't show
- plex.tv: the PIN link, the account, the server list and the address lookup are fixture-tested only.
- A transcode itself: the server downloads its audio codecs from plex.tv on first use, which the offline server can't. CI checks that the server accepts the transcode request (its decision endpoint answers "Conversion OK") and streams the original file.
- How a claimed server treats tokens from shared users and from other devices, and whether those tokens are the newer JWT kind that expires.

## Open (the owner)
- Should the companion ask plex.tv who a token belongs to, so all of an owner's devices share one companion profile? Recommended: not until the owner says so (it makes the companion contact a third party).

## Consequences
- A Plex profile keeps working when the server's address changes, as long as one saved address or plex.tv still finds it.
- A Plex server whose files are replaced gives those tracks new IDs; the library follows on the next sync.
- The Dart, Kotlin and Swift bindings pick up `ServerKind::Plex` and the four `plex_*` calls when the lead regenerates them.
