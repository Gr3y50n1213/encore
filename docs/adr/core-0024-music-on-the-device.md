# ADR core-0024: Music files on the device

Date: 26 November 2026
Status: accepted (Phase 12 stage 4; mock-up 49 approved by the owner on 26 November 2026 with all four recommended choices)

## Context
Phase 12's last source is the listener's own music files on the device, next to a media server in the same profile (plan section 4: "one profile can attach several sources at once", duplicates merged by MusicBrainz ID, then by artist, title and length). Unlike every other source there is no server: nothing to sign in to, no API to page through, nothing to stream from. The files have to be found by the platform, which alone can open them (Android's content addresses, iOS security-scoped bookmarks, desktop folders), and read by the core, which alone knows the library model. The store already keys every song, album and artist by source, so a profile with two sources needs no new schema.

## Decision
1. **Reading a file is the core's; finding it is the platform's.** `encore-sources/src/local/` reads a file it is handed by a path it can open for that one call (on Android `/proc/self/fd/<n>` of a descriptor the app holds open), through Symphonia's format and tag readers. Symphonia is already in the workspace for audio analysis (MPL-2.0); no new library. No audio is decoded, no file is changed, and the core never walks a file system.
2. **What is read** (mock-up 49): title, artists (a tag holding "A; B" or "A / B" is split; "AC/DC" is not), album, album artist, track and disc numbers, year, genres, length (from the container, or counted from its packets when an MP3 has no Xing or VBRI frame), the MusicBrainz recording ID, lyrics (the tag's, else a `.lrc` file of the same name the platform reads), and the front cover (else the first picture, else a `cover.jpg`, `folder.jpg` or the like beside the file). A file with no title is named from its file name ("03 - Artist - Title.mp3"). Formats: MP3, FLAC, M4A (AAC and ALAC), Ogg Vorbis and WAV.
3. **Folders the listener picks** (owner's choice). On Android the folder picker (Storage Access Framework) gives read access to those folders only, kept across restarts; Encore asks for no media permission and never sees voice notes or recordings elsewhere. The `.lrc` files and covers beside the music are readable this way.
4. **The index.** `LocalIndex` (one JSON file in the profile's `local` folder, covers beside it) keeps each folder and each file's address, size, time and tags, so a later look reads only new or changed files. Library IDs are hashes of addresses (`t…` songs, `a…` albums by album artist and title, `r…` artists by name), so nothing that syncs names a folder or a file. A look ends with the list of addresses seen: the others are gone (their plays stay in the history). A folder that can't be reached is marked "Not available right now" and keeps its songs.
5. **A source like the others.** `LocalSource` implements `MediaSource` (`SourceKind::Local`, "local" in the database): a sync hands over the whole index (`full`), a song streams from its own address with no headers, a cover is a `file:` URL, lyrics come from the index. It has no playlists, can't be edited, isn't downloaded and isn't analysed in ranges. It opens with the profile and needs no token.
6. **The same song in both places is listed once and plays from the device** (owner's choice). After every sync the store drops the device's copy of any song a server also has (same song key: MusicBrainz ID, else artist, title and length), and the device's albums and artists that leaves empty (`drop_device_twins`). The index keeps the file, so if the server's copy goes, the device's comes back on the next sync. `stream_for` plays a server's song from the device's copy when there is one (`local = true`, no data used), and such songs count as playable offline.
7. **The phone mark.** `AlbumSummary.on_device` is true for albums from the device's own music (only on this device); the platform marks them beside the artist (mock-up 49, screen 4).
8. **A profile with no server.** `create_device_profile(name)` makes a profile with only the device's music, for "Use music on this phone" on the Connect step (owner's choice); a server can be added later.

## Testing
- `local::tags`: one-second sine tones with tags (`encore-sources/tests/fixtures/local/`, made by `make.sh` with ffmpeg, so they carry no one's music): an MP3 with ID3v2 tags and a cover, an untagged MP3 with no Xing frame, a FLAC with Vorbis comments, lyrics and a picture block, an M4A and an Ogg Vorbis file.
- `local::index` and `local::source`: folders, looks, forgotten files, file-name titles, hashed IDs, the delta, streams, covers and lyrics.
- `encore-store` `the_devices_copy_of_a_servers_song_is_listed_once`; `encore-core` `music_on_the_device_joins_the_profile` (the Jellyfin replay plus the tones: library, phone mark, stream, reopening with no token, removing the last folder) and `a_profile_with_only_the_devices_music`.
