# Phase 9 review: core track

Prompt 9, 11 November 2026. Phase 9's "done when" line is *a widget set to one profile never shows another profile's history, the locked screen shows nothing from the listening history, the sleep timer ends with the fade-out, and no widget or Live Activity makes a network call*. The core track's part covers:
- the sleep timer: state, stop points, fade rule and play-log effect;
- the per-profile widget snapshot: file, covers, privacy and events;
- `play_mix` for widgets and the tile.

The plan is ADR core-0018; the API is CORE-API v7.

**The owner's answers (11 November 2026):** Glance may be added, `POST_PROMOTED_NOTIFICATIONS` may be added, and the Recap widget waits for Phase 11 (the snapshot reserves `recap`).

**Evidence:**
- **Local:** not run for this review.
- **CI:** the core workflow run 43060448177 (commit 4747b85) passed on Linux (make check-core, then Swift, Kotlin and Dart), Windows, Apple and the Android ABIs; its server image job first failed on a runner DNS error and passed when rerun. Bindings for Kotlin, Swift and Dart were regenerated by CI run 43059882967 and committed.
- **Tests:** `core/encore-core/src/api/core/tests/sleep.rs` and `core/encore-core/src/api/core/tests/widgets.rs`, plus two unit tests in `core/encore-core/src/api/core/sleep.rs`.

## Deviations from the plan

1. **A timer per device, not per profile.** Board 31 item 5 says per profile; item 7 says switching profile needs no change. The plan chose per device. Board 31 item 5's wording needs fixing.
2. **Add 15 min in End of song or End of album mode** switches to a time: 15 minutes after the song or album would have ended. The docs didn't say.
3. **`SleepTimerSpec` and `MixRef` are records** (`mode`, `minutes?` and `kind`, `mix_id?`), not enums with data, because Dart's generated enums can't carry data.
4. **The Recap widget is deferred to Phase 11.** The snapshot carries `recap: null`.
5. **The first-sync Live Update was not built** (Android; see its review).
6. **A testing-only `set_sleep_timer_seconds`** was added so CI can run a 15-second timer. Apps never offer it.

## Found and fixed during this phase

1. **A plain pause at the timer's end would have been logged as a skip** (`playlog.rs` closes a paused play as a skip when the next song starts). `sleep_timer_ended` and the paused-timer path close it as ended by the system.
2. **`home()` can't feed a widget:** it calls the network and its set rotates. The snapshot reads local state only.
3. **EXPORT-FORMAT** said `end_reason` is `null` while a play is open. The export writes `inProgress`, which the Android emulator test saw. `docs/core/EXPORT-FORMAT.md` now says so.

## Not claimed

- **Handoff clearing the timer:** no named test (see above).
- **A timer that runs out while paused with the app's process dead:** the core closes the play on the next read or start; no test kills the process. For the owner's device.
- **Real use:** a week of timers and widgets on the owner's devices.
- **Desktop and Apple apps:** they get the timer and snapshot from the core when built; their widgets and Live Activities are their own tracks.
